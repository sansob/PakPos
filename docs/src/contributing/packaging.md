# Package managers

Every release attaches `pakpos-<version>-package-manifests.zip`, generated by
`packaging/make-manifests.py` from the release's `SHA256SUMS.txt`. It contains
ready-to-submit files for four package managers. Publishing them needs
accounts that belong to the maintainers, so it is a manual step.

To regenerate them locally:

```sh
curl -LO https://github.com/sansob/PakPos/releases/download/v0.2.0/SHA256SUMS.txt
python3 packaging/make-manifests.py --version 0.2.0 --sums SHA256SUMS.txt --out manifests
```

## Homebrew (macOS, Linux)

`homebrew/Casks/pakpos.rb` installs the app (and links `pakpos-cli`);
`homebrew/Formula/pakpos-cli.rb` installs only the CLI, on macOS and Linux.

1. Create a tap repository named `homebrew-tap` (e.g. `sansob/homebrew-tap`).
2. Copy `Casks/` and `Formula/` into it and push.
3. Users then run `brew install --cask sansob/tap/pakpos` or
   `brew install sansob/tap/pakpos-cli`.

Getting into the main `homebrew/cask` repository requires a notable, signed
and notarized app; a tap has no such requirement.

## winget (Windows)

`winget/manifests/s/<owner>/PakPos/<version>/` holds the version, installer
(x64 and ARM64 Inno Setup installers) and locale manifests.

1. Fork [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs).
2. Copy the `manifests/…` folder into the fork, then check it with
   `winget validate <folder>` and `winget install --manifest <folder>`.
3. Open a pull request; the winget bots validate and scan the installers.

Later versions can be submitted with `wingetcreate update sansob.PakPos -v <version> -u <urls> --submit`.

## AUR (Arch Linux)

`aur/pakpos-bin/` holds `PKGBUILD` and `.SRCINFO` for a `-bin` package built
from the release tarballs (x86_64 and aarch64). Version `0.2.0-rc.1` becomes
`pkgver=0.2.0rc.1`, because pacman versions cannot contain `-`.

```sh
git clone ssh://aur@aur.archlinux.org/pakpos-bin.git
cp manifests/aur/pakpos-bin/{PKGBUILD,.SRCINFO} pakpos-bin/
cd pakpos-bin && makepkg -si   # test it
git commit -am "pakpos-bin 0.2.0" && git push
```

## Flatpak / Flathub (Linux)

`flatpak/io.github.sansob.PakPos.yml` and the metainfo file build a Flatpak from the
release tarballs:

```sh
flatpak-builder --user --install build-dir io.github.sansob.PakPos.yml
flatpak run io.github.sansob.PakPos
```

The app id uses `io.github.<owner>`, which Flathub can verify through GitHub.
The sandbox gets network access and your home folder (collections, `.proto`
and data files live there). Flathub reviewers usually expect apps that can be
built from source to be built from source; for a Flathub submission, switch
the module to a source build (with `flatpak-cargo-generator` for the Cargo
dependencies) and follow their [submission guide](https://docs.flathub.org/docs/for-app-authors/submission).

## Code signing

Release builds are not code-signed or notarized yet; see the
[installation guide](../installation.md) for the first launch on macOS and
Windows.
